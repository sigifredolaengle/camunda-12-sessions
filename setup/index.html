Preparación de la sala de computadores: Camunda 8 en Windows

Instrucciones para el técnico que prepara la sala del curso Camunda en 12 sesiones.

Qué queda instalado en cada computador:

Programa Versión Para qué
Java (Eclipse Temurin) 21 Lo necesita Camunda 8 Run 8.9
Camunda 8 Run 8.9 El motor de procesos, con Operate y Tasklist (se usan en el navegador)
Camunda Desktop Modeler 5.52 o posterior El editor de diagramas
Plugin Token Simulation 0.24.0 Simulación de diagramas dentro del Modeler

Todo es gratuito para uso educativo. Nada necesita internet durante la clase: todo corre en el mismo computador (localhost).

0. Antes de empezar

Requisitos de cada computador:

  • Windows 10 u 11 de 64 bits.
  • 8 GB de RAM como mínimo (16 GB recomendados).
  • Al menos 10 GB libres en el disco, siempre. Camunda se apaga solo si el disco queda casi lleno: arranca, funciona unos minutos y se detiene sin mensaje claro. En el registro (C:\camunda\c8run-8.9…\log\camunda.log) aparece «Not enough disk space available».
  • El puerto 8080 libre. Para comprobarlo, en PowerShell: netstat -ano | findstr :8080 no debe mostrar nada.
  • Permisos de administrador para instalar.
  • Acceso a https://sigifredolaengle.github.io (el sitio del curso). Se utiliza para consultar las guías; el inicio de Camunda no descarga ni despliega correctores.
  • Que se pueda escribir en C:\camunda durante la sesión.

Preguntas para el técnico (por favor, responder al profesor antes de instalar):

  1. ¿Los computadores tienen un programa que restaura el equipo al reiniciar (Deep Freeze, Reboot Restore, Windows Unified Write Filter u otro)? Si es así:
    • Hay que instalar todo con el equipo descongelado, para que la instalación quede en la imagen.
    • Lo que los estudiantes hagan en clase (modelos desplegados, instancias) se borra al reiniciar. Para el curso eso no es un problema, pero el profesor necesita saberlo.
    • La carpeta C:\camunda debe quedar en la imagen, pero Camunda escribe datos dentro de ella (camunda-data y log) mientras corre: debe poder escribir ahí durante la sesión.
  2. ¿Los estudiantes entran con una cuenta común o cada uno con su cuenta? Las instrucciones de abajo dejan todo para todas las cuentas del computador; si algo queda solo en la cuenta del instalador (por ejemplo, la asociación de archivos .bpmn), hay que repetirlo en la cuenta común.
  3. ¿Hay una política que bloquee programas descargados (SmartScreen, AppLocker, antivirus)? c8run.exe y Camunda Modeler.exe vienen en un .zip, sin instalador.

1. Java 21

Página oficial: https://adoptium.net/temurin/releases/?version=21&os=windows&arch=x64.

Opción A, instalador .msi: descargar JDK 21, Windows x64, .msi. En el instalador:

  • elegir Install for all users (instalar para todos los usuarios);
  • en las funciones, activar Set JAVA_HOME variable (viene desactivada).

Opción B, winget (PowerShell como administrador):

winget install EclipseAdoptium.Temurin.21.JDK --scope machine

Si JAVA_HOME quedó vacía, definirla como variable del sistema (PowerShell como administrador, con el nombre exacto de la carpeta):

setx /M JAVA_HOME "C:\Program Files\Eclipse Adoptium\jdk-21.0.x.x-hotspot"

Comprobar en una ventana de PowerShell nueva:

java -version
echo $env:JAVA_HOME

La primera línea debe decir 21; la segunda, la carpeta de Java.

2. Camunda 8 Run 8.9

Descarga directa (Windows x64): https://downloads.camunda.cloud/release/camunda/c8run/8.9/camunda8-run-8.9-windows-x86_64.zip. Instrucciones oficiales: https://docs.camunda.io/docs/self-managed/quickstart/developer-quickstart/c8run/install-start/.

Descomprimir en C:\camunda (la ruta no debe tener espacios). En PowerShell:

Expand-Archive "$env:USERPROFILE\Downloads\camunda8-run-8.9-windows-x86_64.zip" -DestinationPath C:\camunda

Queda una carpeta C:\camunda\c8run-8.9.… con c8run.exe dentro. Los scripts del paso 5 buscan Camunda ahí.

Primer arranque de prueba:

cd C:\camunda\c8run*
.\c8run.exe start

Tarda entre uno y tres minutos y termina con «All processes are running and healthy». Si SmartScreen detiene c8run.exe: Más información → Ejecutar de todas formas. Si el firewall de Windows pregunta, no hace falta abrir nada hacia la red: todo funciona dentro del mismo computador.

Para detenerlo: .\c8run.exe stop.

Problemas frecuentes: https://docs.camunda.io/docs/self-managed/quickstart/developer-quickstart/c8run-troubleshooting/.

3. Camunda Desktop Modeler

Página de descargas: https://camunda.com/download/modeler/. Para Windows solo hay un .zip (sin instalador), por ejemplo https://downloads.camunda.cloud/release/camunda-modeler/5.53.0/camunda-modeler-5.53.0-win-x64.zip. El curso se probó con la 5.52; sirve cualquier 5.x igual o posterior.

  1. Descomprimir en C:\camunda\modeler (clic derecho → Extraer todo). Queda C:\camunda\modeler\Camunda Modeler.exe.
  2. Crear un acceso directo a Camunda Modeler.exe en el escritorio público (C:\Users\Public\Desktop), para que aparezca en todas las cuentas.
  3. Asociar los archivos .bpmn, .dmn y .form con el Modeler: clic derecho sobre thread-s01.bpmn → Abrir con → Elegir otra aplicación → buscar C:\camunda\modeler\Camunda Modeler.exe → Siempre. Repetir con un .dmn y un .form si se dispone de ellos. Esta asociación queda en la cuenta que la hace: si los estudiantes usan otra cuenta, repetirla en esa cuenta.

4. Plugin Token Simulation

Con el Modeler cerrado, descomprimir token-simulation-v0.24.0.zip dentro de C:\camunda\modeler\resources\plugins (si no existe la carpeta plugins, crearla). El .zip trae la carpeta token-simulation, así que queda así (todas las cuentas del computador lo ven):

C:\camunda\modeler\resources\plugins\token-simulation\index.js

Debe haber un solo nivel de carpeta token-simulation (no token-simulation\token-simulation).

Comprobar: abrir el Modeler y un diagrama .bpmn. Arriba a la izquierda aparece el interruptor Token Simulation, y el menú Plugins lo lista.

El plugin es de código abierto (licencia MIT): el .zip contiene la versión 0.24.0 publicada en npm (camunda-modeler-token-simulation-plugin), sin cambios. Repositorio oficial: https://github.com/camunda/camunda-modeler-token-simulation-plugin.

5. Accesos directos para iniciar y detener Camunda

Camunda no arranca solo al encender el computador, y conviene que sea así: ocupa entre 2 y 4 GB de RAM y la sala la usan otros cursos. Se inicia con un doble clic al empezar la clase.

  1. Copiar iniciar-camunda.bat y detener-camunda.bat a C:\camunda.
  2. Crear en el escritorio público (C:\Users\Public\Desktop) dos accesos directos:
    • Iniciar Camunda → C:\camunda\iniciar-camunda.bat
    • Detener Camunda → C:\camunda\detener-camunda.bat

iniciar-camunda.bat arranca Camunda, espera a que esté listo (uno a tres minutos) y abre dos pestañas del navegador.

Inicio simplificado. El alumno inicia el servidor, abre Desktop Modeler y consulta la guía. El acceso directo no descarga ni despliega procesos de verificación, tampoco desde copias antiguas en caché. Las clases 1 y 3 no tienen evaluación ni registro por sesión. Los modelos y formularios del ejercicio se despliegan desde el Modeler cuando lo indica la guía.

Las pestañas:

  • Operate en http://localhost:8080/operate
  • Tasklist en http://127.0.0.1:8080/tasklist

Las dos direcciones llevan al mismo Camunda; se usan dos distintas para que el navegador mantenga abiertas las dos sesiones a la vez. Si Camunda ya estaba corriendo, solo abre las pestañas. Usuario y clave: demo / demo.

6. Verificación

Con Camunda iniciado (acceso directo Iniciar Camunda):

Verificación Cómo Resultado esperado
Java java -version en PowerShell 21
Operate abrir http://localhost:8080/operate, entrar con demo / demo el panel de Operate
Tasklist abrir http://127.0.0.1:8080/tasklist, entrar con demo / demo una lista de tareas vacía
API curl.exe -i http://localhost:8080/v2/topology en PowerShell HTTP/1.1 200 y el estado del clúster

En PowerShell hay que escribir curl.exe, no curl: curl es otro comando.

Prueba completa con un modelo:

  1. Abrir thread-s01.bpmn con doble clic: se abre en el Modeler.
  2. Clic en el ícono del cohete (Deploy), abajo a la izquierda. Destino: Camunda 8 Self-Managed, http://localhost:8080, sin autenticación. En las versiones recientes del Modeler aparece ya configurado como c8run (local).
  3. Clic en el triángulo (Start instance), al lado del cohete. En la ventana que se abre, dejar vacía la caja Variables y hacer clic en Start.
  4. En Tasklist aparece la tarea Review request. Asignarla (Assign to me) y completarla (Complete task).
  5. En Operate, la instancia de Student request aparece como terminada.

Si los cinco pasos funcionan, el computador está listo. Al terminar, hacer clic en Detener Camunda.

Si algo falla

Síntoma Causa probable Qué hacer
Camunda arranca y se apaga solo a los pocos minutos Poco espacio en el disco Liberar espacio (al menos 10 GB libres) e iniciar de nuevo
c8run.exe dice que no encuentra Java JAVA_HOME vacía o de otra versión Revisar el paso 1, en una ventana nueva
El puerto 8080 está ocupado Otro programa lo usa Avisar al profesor: Camunda puede usar otro puerto, pero hay que cambiarlo en todo el curso
El Modeler no muestra Token Simulation Plugin en la carpeta equivocada o con dos niveles Revisar la ruta del paso 4 y reiniciar el Modeler
El despliegue falla con «Attribute ‘type’ must be present» El archivo .bpmn se modificó Volver a descargar thread-s01.bpmn

Ante cualquier duda, escribir al profesor del curso.
